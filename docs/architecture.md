# 架构说明

## 五层结构

```
┌─ ① 触发层 ─────────────────────────────┐
│  CLI（当前） / Webhook（规划中）          │
└──────────────┬─────────────────────────┘
┌──────────────▼─────────────────────────┐
│  ② 理解层：自然语言变更 → 结构化字段       │
│  tools/llm.parse_change()               │
└──────────────┬─────────────────────────┘
┌──────────────▼─────────────────────────┐
│  ③ 规划层：影响面 → 执行计划              │
│  agent/planner.py                       │
│  变更类型 → 场景清单 / 档位 / 阈值 / 顺序   │
└──────────────┬─────────────────────────┘
┌──────────────▼─────────────────────────┐
│  ④ 执行层：DAG + 重试 + 自愈              │
│  agent/executor.py                      │
│  录制就绪 → 压测 → diff                   │
└──────────────┬─────────────────────────┘
┌──────────────▼─────────────────────────┐
│  ⑤ 判读层：阈值规则 → 结论 + 建议          │
│  agent/judge.py                         │
└──────────────┬─────────────────────────┘
         ┌─────▼─────┐
         │ 人工审批入口 │
         └───────────┘
```

## 数据流

```
"图A 召回算子改动"
   ↓ parse_change
{kind: recall}
   ↓ planner（查 data/mapping.csv）
Plan{scenes:[直播召回-1,直播召回-2,商详召回-1], qps:[1200,1600], threshold:1%}
   ↓ executor
{check_recording: {...}, load_test: {...}, diff: {...}}
   ↓ judge（阈值规则）
Verdict{passed, reasons, suggestions}
   ↓
卡片输出 / 审批入口
```

## 工具接口

所有工具实现 `Tool.run(params) -> ToolResult`：

| 工具 | 输入 | 输出 |
|---|---|---|
| r2 | scene | status, record_success |
| forcebot | scene, qps | avg, p99, cpu |
| diff | scene, fields, ordered | diff_rate, top100_consistent |

Mock 与真实实现同签名，切换只改 `agent/main.py` 里的实例化。

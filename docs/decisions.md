# 设计决策

## D1 规则优先，模型兜底

| 环节 | 用什么 | 理由 |
|---|---|---|
| 变更 → 场景 | 规则表 + LLM 兜底 | 80% 可枚举；未知变更回退全量 |
| 参数选择 | 规则 | 参数错 → 结论错 |
| 执行顺序 | 确定性 DAG | 顺序错 → 事故 |
| 结果判读 | 规则阈值 | 必须确定 |
| 归因解释 | LLM 辅助 | 仅作建议 |
| 是否放行 | 规则 + 人 | 绝不由模型放行 |

## D2 执行与判读分离

执行层只返回数据，判读层只看数据。好处：判读逻辑可以脱离平台单测。

## D3 失败方向：宁慢不漏

意图不明确 / 变更类型未知 → 跑全量场景。
漏测的代价是不可逆的，多跑的代价只是时间。

## D4 不是门禁

Agent 只提供执行能力。门禁必须由发布流程强制触发，
否则会退化成"想起来才跑"。
